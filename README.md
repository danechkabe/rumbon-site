# Rumbon · Румбон

Адаптивний статичний сайт кімнат у Лісабоні. Англійська — за замовчуванням, українська `/uk/`, португальська `/pt/`. Без фільтрів, платежів та акаунтів. Для збірки потрібен лише Python 3.12+; npm не потрібен.

## Запуск

```sh
python3 -m unittest discover -s tests -v
python3 scripts/build.py
python3 -m http.server 4173 --directory dist
```

Відкрийте http://localhost:4173. `dist/` — готові файли для публікації. Стабільні адреси: `/rooms/roma-areeiro-600/`, `/rooms/roma-areeiro-750/`, `/rooms/roma-areeiro-650/`. Кожна має українську й португальську версію. Сторінки квартир генеруються як `/apartments/<id>/` лише для підтверджених опублікованих квартир.

Усі три початкові записи мають статус «Вільна зараз», а «Опубліковано» вимкнено. Без адрес, фото й підтвердження квартири це підготовчі записи. У локальних стартових даних вони показані з нейтральними заглушками та приміткою про уточнення даних. Не припускаємо, що вони належать до однієї квартири.

`data/notion-config.json` містить тільки несекретні ID. OAuth-підключення Notion у Codex не дає GitHub Actions токен API.

### Увімкнення синхронізації

1. Створіть внутрішню інтеграцію Notion у https://www.notion.so/profile/integrations з дозволом читати контент.
2. У Notion на сторінці Rumbon → ••• → Connections додайте інтеграцію. Вона повинна мати доступ до обох баз. Саму сторінку не публікуйте.
3. У GitHub → репозиторій → Settings → Secrets and variables → Actions → New repository secret. Назва **`NOTION_TOKEN`**, значення — токен інтеграції.
4. На вкладці Variables додайте **`NOTION_SYNC_ENABLED`** = `true`. Це заборонить повертати початкові локальні оголошення, якщо секрет випадково зникне.
5. ID баз уже задано. Для інших баз можна створити змінні `NOTION_ROOMS_DATA_SOURCE_ID` і `NOTION_APARTMENTS_DATA_SOURCE_ID`.
6. Actions → **Sync Notion and publish Rumbon** → **Run workflow**. Автоматичний розклад — раз на 6 годин о 00:17, 06:17, 12:17, 18:17 UTC. GitHub може затримувати запуски; у неактивних публічних репозиторіях GitHub може призупинити розклад.

З токеном збірка показує **лише** опубліковані завершені записи з Notion. Порожній результат означає порожній список, без підміни початковими даними. Чернетки завжди приховані. Помилка API або завантаження фото зупиняє збірку й зберігає попередню публікацію. Справжні фото копіюються в статичні файли; тимчасові URL Notion не передаються браузеру.

### Що заповнити перед публікацією

Квартира: назва, незмінний ID латиницею з дефісами, район, точна адреса та загальна кількість кімнат. Кімната: ID, Relation рівно до однієї опублікованої квартири, заголовок/опис EN, ціна EUR, справжні фото та статус. Для «Вільна з дати» потрібна коректна дата. Відсутні UK/PT переклади замінюються EN. Координати необов’язкові, але без них кімната не матиме точки. «Ні» для зручності — підтверджена відсутність, порожнє поле — невідомо.

Початкові підтверджені дані: RA-600 — €600, двоярусне ліжко, 1 людина; RA-750 — €750, двоспальне ліжко, власна ванна, велика шафа й мініхолодильник; RA-650 — €650, двоспальне ліжко, без власної ванної. Район усіх — Roma-Areeiro. Потрібно додати адреси, фото, підтвердити квартири, за бажанням метро, координати й решту характеристик. Не змінюйте ID після публікації, інакше зміниться URL.

## GitHub Pages

Workflow `.github/workflows/pages.yml`: push у `main`, ручний запуск і розклад. У Settings → Pages → Build and deployment → Source виберіть **GitHub Actions**. Workflow сам підставляє правильний базовий шлях, зокрема `/rumbon-site`. Секрет Notion потрібен лише для синхронізації; без нього сайт збирається з початкових локальних даних.

Ручна збірка для Pages:

```sh
SITE_URL=https://danechkabe.github.io/rumbon-site BASE_PATH=/rumbon-site python3 scripts/build.py
```

Поточні підтверджені результати публікації дивіться в `docs/STATUS.md`. Наявність workflow у файлах сама по собі не підтверджує ввімкнену синхронізацію.

## Мапа та перевірки

Leaflet 1.9.4 з OpenStreetMap, без API-ключа. Leaflet і його ліцензію збережено локально в `assets/vendor/`. Центр загальної мапи — Лісабон; це не координати кімнат. Точки беруть лише з наявних числових широти/довготи. Карусель об’єднує кімнати тільки за підтвердженим Relation квартири. За відсутності точок показується пояснення.

`tests/test_site.py` перевіряє правила видимості, дати, переклади, захист від HTML-вставок, відсутні дані, Relation, підрахунок вільних кімнат, пагінацію API й безпечну поведінку без токена. `qa/browser-check.cjs` перевіряє вузькі телефони, планшет і десктоп, перемикання мов, WhatsApp та прямі посилання. Шляхи до встановлених Playwright/Chromium можна перевизначити через `PLAYWRIGHT_MODULE` і `CHROMIUM_PATH`; залежності потрібні лише для QA.
